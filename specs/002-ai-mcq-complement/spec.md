# Feature Specification: AI MCQ Complement for Existing Quizzes

**Feature Branch**: `002-ai-mcq-complement`

**Created**: 2026-06-27

**Status**: Draft

**Input**: User description: "Expert educational assessment assistant that analyzes lecture text extracted from a Word document and generates a new set of high-quality Multiple-Choice Questions (MCQs) to complement an existing quiz that already contains Short Answer questions. Output is MCQs only, appended safely to the quiz by the backend."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Generate MCQs to complement an existing quiz (Priority: P1)

An instructor opens a quiz that already contains Short Answer questions (generated by the existing AI quiz generator or authored manually). They upload the same or a related lecture `.docx` and request "Generate MCQs". The system analyzes the extracted text and produces a set of strictly fact-grounded Multiple-Choice Questions, each with exactly 4 options (A–D), a correct answer letter, a 1-sentence justification drawn from the source text, and a difficulty tag. The instructor reviews the MCQ draft, edits as needed, and confirms — at which point the backend appends only the new MCQs to the existing quiz without disturbing the Short Answer questions already on it.

**Why this priority**: This is the core value. Instructors who used the initial generator for Short Answer questions can now round out their quiz with MCQs in minutes, without re-generating or overwriting the work already done.

**Independent Test**: An instructor opens a quiz with 5 existing Short Answer questions, uploads a `.docx`, clicks "Generate MCQs", reviews a draft of MCQs (each with 4 options, correct answer, justification, and difficulty), confirms, and the quiz now contains the original 5 SA questions plus the new MCQs — all visible in the quiz editor and playable by students.

**Acceptance Scenarios**:

1. **Given** a quiz with existing Short Answer questions and a valid `.docx` lecture file, **When** the instructor uploads the file and requests MCQ generation, **Then** the system returns a draft containing only MCQs, each with exactly 4 options labeled A–D, one correct answer letter, a 1-sentence justification referencing the source text, and a difficulty tag (Easy, Medium, or Hard).
2. **Given** a completed MCQ draft, **When** the instructor confirms "Append to quiz", **Then** the new MCQs are persisted to the existing quiz without modifying, reordering, or deleting any pre-existing questions (Short Answer or otherwise), and the quiz's question count reflects the addition.
3. **Given** an uploaded `.docx` that yields no extractable text, **When** MCQ generation is requested, **Then** the system refuses with a clear, actionable error message and does not append any partial questions to the quiz.
4. **Given** a student or unauthenticated user, **When** they attempt to access the MCQ complement endpoint via UI or direct API call, **Then** the system denies access with an authorization error.

---

### User Story 2 - Review, edit, and selectively accept generated MCQs (Priority: P2)

Before confirming, the instructor reviews each generated MCQ in a draft view. They can edit any field (question stem, options A–D, correct answer letter, justification, difficulty), delete individual MCQs they dislike, or regenerate a single MCQ while keeping the rest intact. Only the MCQs the instructor explicitly approves are appended to the quiz.

**Why this priority**: AI-generated questions are rarely perfect. Without an edit-before-append loop, instructors lose trust in the feature and fall back to manual authoring.

**Independent Test**: Starting from a generated MCQ draft of 8 questions, the instructor edits 2 questions' stems, deletes 1, regenerates 1, and confirms. The quiz receives exactly 7 new MCQs (8 original minus 1 deleted, with 1 of the remaining regenerated as a replacement). The 7 appended MCQs reflect all edits, and the original SA questions are unchanged.

**Acceptance Scenarios**:

1. **Given** a draft of 8 MCQs, **When** the instructor deletes 2 and confirms, **Then** 6 MCQs are appended to the quiz and the 2 deleted ones are discarded.
2. **Given** a draft MCQ with an incorrect justification, **When** the instructor edits the justification and saves, **Then** the edited justification persists in the draft and is used when appending to the quiz.
3. **Given** a draft MCQ the instructor finds irrelevant, **When** they click "Regenerate this question", **Then** only that MCQ is replaced by a new AI-generated MCQ grounded in the source text, and all other draft MCQs remain untouched.

---

### User Story 3 - Difficulty-balanced MCQ mix (Priority: P2)

The instructor can specify the desired difficulty distribution before generation (e.g., 3 Easy, 3 Medium, 2 Hard) or accept the system default. The generated MCQs respect this distribution, and the difficulty tag on each question is visible and editable in the draft.

**Why this priority**: Pedagogically effective quizzes require a deliberate difficulty gradient. Without this, the generator may cluster questions at one cognitive level, reducing assessment value.

**Independent Test**: The instructor requests 8 MCQs with 3 Easy / 3 Medium / 2 Hard. The draft contains exactly that distribution. The instructor re-tags one Medium as Hard and confirms — the appended questions carry the updated tags.

**Acceptance Scenarios**:

1. **Given** a requested distribution of 3 Easy, 3 Medium, 2 Hard, **When** the draft is generated, **Then** the draft contains exactly 3 Easy, 3 Medium, and 2 Hard MCQs.
2. **Given** a generated MCQ tagged as Easy, **When** the instructor changes its tag to Medium, **Then** the updated tag persists in the draft and in the final appended question.
3. **Given** the instructor does not specify a distribution, **When** they request generation, **Then** the system applies a balanced default (roughly equal thirds across Easy, Medium, Hard).

---

### Edge Cases

- **Source text too short for requested count**: the document yields fewer groundable facts than the requested MCQ count → generate as many as can be grounded, surface the shortfall in the UI, and let the instructor decide whether to keep them or upload a richer source.
- **Distractor plausibility**: every distractor (incorrect option) MUST be factually wrong according to the source text but plausible enough to test comprehension — options that are obviously absurd or off-topic are a quality defect.
- **Duplicate questions across SA and MCQ**: if the source text is the same as what was used for the existing SA questions, the generated MCQs MUST NOT ask the same question in MCQ form that already exists as a Short Answer on the quiz. The system MUST compare new MCQ stems against existing question stems and drop or replace duplicates.
- **All 4 options identical or near-identical**: a generated MCQ where two or more options are semantically identical MUST be dropped or regenerated before showing in the draft.
- **Correct answer not among options**: if the AI returns a correct-answer letter that doesn't match any option, the question MUST be dropped before showing in the draft.
- **Quiz is published / has active attempts**: appending MCQs to a published quiz MUST NOT silently affect in-progress or already-submitted student attempts. The system MUST warn the instructor that the quiz is published and that new questions will only appear on future attempts.
- **Non-English / mixed-language source**: generated MCQs, options, and justifications MUST be in the same language as the source text's dominant language.
- **AI provider failure**: same handling as the existing generator — no partial draft persisted, specific error shown, daily quota not consumed for provider-side failures.
- **Concurrent complement requests on the same quiz**: if two instructors (or the same instructor in two tabs) attempt to complement the same quiz simultaneously, only one set of MCQs should be appended; the second request MUST detect the conflict and inform the user.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Instructors MUST be able to trigger MCQ generation from a quiz that already contains questions, by uploading a `.docx` lecture file. The system MUST accept the same `.docx` format and use the same text-extraction pipeline as the existing AI quiz generator (FR-002 of spec 001).
- **FR-002**: The generated output MUST contain only Multiple-Choice Questions. Each MCQ MUST have exactly 4 options labeled A, B, C, and D. Exactly one option MUST be marked as correct.
- **FR-003**: Each MCQ MUST include a correct-answer letter (A, B, C, or D) and a 1-sentence justification that directly references or paraphrases a fact stated in the source text.
- **FR-004**: Questions MUST be derived exclusively from clear facts directly mentioned in the extracted text. The system MUST NOT introduce outside knowledge, assumptions, or inferences not supported by the document.
- **FR-005**: Distractors (incorrect options) MUST be realistic and plausible — they should relate to the topic and be the kind of mistake a student who partially understood the material might make. Absurd, off-topic, or trivially eliminable options are a quality defect.
- **FR-006**: Each MCQ MUST be tagged with exactly one difficulty level: Easy (factual recall), Medium (comprehension/understanding), or Hard (application/analysis). The instructor MUST be able to specify the desired count per difficulty before generation and MUST be able to re-tag any question in the draft.
- **FR-007**: The system MUST present MCQs in a draft review view before appending. The instructor MUST be able to edit (stem, options, correct answer, justification, difficulty), delete, or regenerate any individual MCQ in the draft.
- **FR-008**: On confirmation, the system MUST append the approved MCQs to the existing quiz without modifying, reordering, or removing any pre-existing questions. The append operation MUST be atomic — either all approved MCQs are added or none are.
- **FR-009**: The system MUST compare generated MCQ stems against existing question stems on the target quiz and MUST drop or flag any MCQ that substantially duplicates an existing question (regardless of type).
- **FR-010**: Generation MUST run asynchronously, consistent with the existing generation architecture (async job, polling, no held HTTP connection). The UI MUST show progress and the completed draft without a page reload.
- **FR-011**: If the quiz is published and has active or completed student attempts, the system MUST warn the instructor before appending that new questions will only appear on future attempts and will not retroactively affect past submissions.
- **FR-012**: Authorization MUST be enforced server-side: only `instructor` (owner of the quiz) and `admin` roles may trigger MCQ complement generation. Students and unauthenticated users MUST receive an authorization error.
- **FR-013**: AI consent MUST be checked before generation: the system MUST reuse the existing AI Processing Consent mechanism (spec 001, FR-022). If the user has not yet acknowledged consent (or the consent text version has changed), the consent banner MUST be shown before proceeding.
- **FR-014**: Quota and document-size limits MUST be enforced: MCQ complement generations MUST count against the same daily generation quota and maximum document size as full quiz generations (spec 001, FR-012).
- **FR-015**: An audit record MUST be created for every MCQ complement generation attempt, capturing the same fields as the existing generation audit (spec 001, FR-013) plus the target quiz ID and the count of questions appended.
- **FR-016**: All user-facing strings (UI labels, validation messages, error toasts, draft review text) MUST be served through the existing i18n layer and MUST render in the user's locale.
- **FR-017**: The system MUST validate every generated MCQ before including it in the draft: (a) exactly 4 distinct options, (b) correct-answer letter matches one of the options, (c) justification is present and ≤2 sentences, (d) no two options are semantically identical. Questions failing validation MUST be silently dropped and the shortfall noted in the draft summary.

### Key Entities

- **MCQ Draft**: A provisional collection of generated Multiple-Choice Questions awaiting instructor review before being appended to a target quiz. Each draft is tied to a generation job, a source document, and a target quiz.
- **MCQ Draft Question**: A single generated MCQ carrying: stem text, 4 options (A–D), correct-answer letter, 1-sentence justification, difficulty tag, and an instructor state (untouched / edited / approved / deleted / regenerated).
- **Target Quiz**: The existing quiz (containing Short Answer or any other question types) to which the approved MCQs will be appended. The complement operation references but does not own this entity.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: An instructor can generate and append MCQs to an existing quiz in under 3 minutes for a typical lecture document (≤30 pages), including draft review time.
- **SC-002**: 100% of generated MCQs have exactly 4 distinct options with one correct answer that matches a stated fact in the source document.
- **SC-003**: In pilot use, at least 85% of generated MCQs are accepted by the instructor without edits to the stem or options (measured as accepted-without-edit ÷ total generated, rolling 7-day window).
- **SC-004**: Zero generated MCQs reference facts not present in the source document (measured by instructor "ungrounded" rejections; target: <1% over a rolling 30-day window).
- **SC-005**: Generation completes — or fails with a specific error — within 45 seconds at the 95th percentile for documents up to 50 pages (MCQ-only generation is faster than full mixed-type generation).
- **SC-006**: Zero existing questions on the target quiz are modified, reordered, or deleted by the append operation (verified by automated pre/post comparison in integration tests).
- **SC-007**: Zero unauthorized accesses: students and unauthenticated users cannot trigger MCQ complement generation through any entry point.

## Assumptions

- **Existing quiz generator is deployed**: This feature assumes the full AI quiz generator (spec 001) is implemented and operational. It reuses the same text-extraction pipeline, AI provider integration, consent mechanism, quota enforcement, and audit infrastructure.
- **Same AI provider and model**: MCQ complement generation uses the same AI provider (OpenAI GPT-4.1 with Structured Outputs) and prompt infrastructure as spec 001; a separate MCQ-specific prompt template is required but the provider plumbing is shared.
- **Append-only operation**: The complement feature never replaces or modifies existing questions on the target quiz. It is purely additive.
- **Default MCQ count**: When the instructor does not specify, the system defaults to 8 MCQs with a roughly balanced difficulty distribution (3 Easy / 3 Medium / 2 Hard).
- **Shared quota**: MCQ complement generations and full quiz generations share a single daily quota pool per instructor; they are not tracked separately.
- **Source document is not stored long-term**: The uploaded `.docx` is processed and discarded after text extraction, consistent with spec 001's default retention behavior.
- **Duplicate detection is stem-based**: Duplicate detection between new MCQs and existing quiz questions uses semantic similarity of question stems; it does not require exact string matching.
- **Single quiz target**: Each MCQ complement generation targets exactly one quiz; batch-appending MCQs to multiple quizzes from a single generation is out of scope.
